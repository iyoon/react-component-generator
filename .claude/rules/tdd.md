# TDD Rule

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.** 단계를 건너뛰거나 순서를 바꾸거나 "이번만" 예외를 두지 않는다.

## 우선순위

프로젝트의 `CLAUDE.md` / `AGENTS.md`에 TDD 규칙이 있으면 **그 규칙이 우선**한다. 이 파일은 프로젝트 규칙이 없을 때 쓰는 **기본값(fallback)** 이다. 둘이 충돌하면 프로젝트 규칙을 따르고, 충돌하지 않는 부분은 이 파일을 따른다.

## 적용 기준

### TDD 필수

- **비즈니스 로직**: 조건 분기, 계산, 상태 전이, 검증
- **API**: 엔드포인트, 요청/응답 처리, 에러 처리
- **유틸 함수**: 파싱, 변환, 포맷팅 등 순수 함수
- **버그 수정**: 버그를 재현하는 실패 테스트를 먼저 작성한 뒤 고친다

### TDD 불필요

- **타입 정의**: `type`, `interface` 선언만 있는 파일
- **설정 파일**: 빌드·린트·환경 설정
- **순수 UI**: 로직 없이 마크업과 스타일만 있는 컴포넌트
- **SQL**: 스키마·마이그레이션·단순 쿼리

판단이 애매하면 로직이 있는 것으로 보고 **TDD를 적용**한다.

## RED-GREEN-REFACTOR

### 1. RED: 실패하는 테스트 작성

- **하나의 동작 = 하나의 테스트**. 한 테스트에 여러 동작을 섞지 않는다.
- 테스트 이름은 동작을 설명한다 (`장바구니가 비면 총액은 0이다`).
- **반드시 실행해서 실패를 확인한다.** 실행하지 않은 테스트는 테스트가 아니다.
- **실패 이유가 "기능 미구현"이어야 한다.** 문법 오류, import 오류, 오타로 실패하면 테스트부터 고친다.
- 테스트가 처음부터 통과하면 아무것도 검증하지 못한 것이다. 테스트를 고친다.

### 2. GREEN: 통과시키는 최소 코드

- 테스트를 통과시키는 **최소한의 코드만** 작성한다.
- **YAGNI**: 지금 테스트가 요구하지 않는 기능, 옵션, 추상화를 추가하지 않는다.
- **신규 테스트와 기존 테스트가 모두 통과하는지** 전체를 실행해 확인한다.
- 다른 테스트가 깨지면 이번 변경이 원인이다. 먼저 해결하고 다음으로 넘어간다.

### 3. REFACTOR: 정리

- 중복 제거, 이름 개선, 헬퍼 추출만 한다.
- **모든 테스트가 green인 상태를 유지한다.** 수정할 때마다 실행한다.
- **새 동작을 추가하지 않는다.** 새 동작은 다음 RED에서 시작한다.

### 4. 반복

다음 동작에 대한 **RED로 돌아간다.** 요구사항의 모든 동작이 테스트로 덮일 때까지 반복한다.

## 삭제 강제 규칙

**테스트보다 프로덕션 코드를 먼저 작성했다면 그 코드를 삭제하고 RED부터 다시 시작한다.**

- **"참고용"으로 남겨두는 것도 금지한다.** 주석 처리, 별도 파일 보관, 복사해 두고 보면서 다시 쓰기 모두 포함한다.
- 삭제한 코드를 기억에서 되살려 그대로 다시 쓰지 않는다. 테스트가 요구하는 만큼만 새로 작성한다.

## 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트가 필요 없다" | 단순한 코드는 테스트도 단순해서 30초면 쓴다. 단순한 코드가 가장 먼저 바뀌고 가장 먼저 깨진다. |
| "나중에 테스트를 추가하겠다" | 나중에 쓴 테스트는 이미 통과하는 코드에 맞춘 것이라 실패를 본 적이 없다. 아무것도 증명하지 못하고, 나중은 오지 않는다. |
| "시간이 없다" | 디버깅과 회귀 수정에 드는 시간이 테스트 작성 시간보다 크다. 급할수록 안전망이 필요하다. |
| "삭제하면 낭비다" | 이미 쓴 시간은 매몰 비용이다. 검증되지 않은 코드를 유지하는 비용이 더 크다. 테스트 우선으로 다시 쓰면 보통 더 빠르고 단순하다. |
| "프로토타입이다" | 프로토타입은 버리는 코드일 때만 프로토타입이다. 남을 코드라면 프로덕션 코드와 똑같이 TDD를 적용한다. |

## 완료 전 확인

- [ ] 모든 새 동작에 대해 먼저 실패를 확인한 테스트가 있다
- [ ] 신규 + 기존 테스트가 모두 통과한다 (이번에 실행한 결과로 확인)
- [ ] 테스트 전에 작성한 프로덕션 코드가 남아 있지 않다
